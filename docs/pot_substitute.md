# 가변저항 대체 방법과 도착 후 할 일

> 가변저항(포텐셔미터) 모듈은 아직 배송 전이다. 실습은 이 문서의 대체 방법으로 그대로 진행하고, 가변저항이 도착하면 §3 체크리스트대로 붙인다.

---

## 1. 영향받는 범위

가변저항은 **목표값(듀티, 목표 RPM)을 손으로 돌려 넣는 입력 장치**로만 쓰인다. 그래서 입력 방법만 바꾸면 된다.

| Day | 원래 쓰임 | 대체 방법 | 영향 |
|---|---|---|---|
| 1, 2 | — | — | 없음 |
| 3 | ADC 실습 대상 | **S-3** 내장 온도센서 + VREFINT, 3채널 스캔 | 내용이 오히려 늘어남 |
| 4 | 듀티 조절 | **S-1** UART `d` 명령, 또는 **S-2** 버튼 | 없음 |
| 5 | (Day 4 방식 그대로) | S-1 | 없음 |
| 6 | 목표 RPM 입력 | **S-1** UART `r` 명령 | 스텝 응답 재현성이 더 좋아짐 |
| 7, 8 | — | — | 없음 |
| 9 | 소형 보드의 명령 입력 | **S-4** 고정 테스트 시퀀스 | 없음 |
| 10 | — | — | 없음 (S-4 시퀀스가 FI-07 시험에 도움됨) |

## 2. 대체 방법

### S-1. UART 명령 입력 (권장, Day 4 전에 만들기)

시리얼 터미널에서 명령을 쳐서 듀티와 목표 RPM을 넣는다. 가변저항이 와도 **테스트용 입력으로 계속 쓴다**. 같은 숫자를 매번 정확히 넣을 수 있어서 시험 결과를 재현하기 좋다.

**명령 사양**

| 명령 | 뜻 | 범위 | 예 | 쓰는 날 |
|---|---|---|---|---|
| `d<값>` | 듀티(‰), 부호는 방향 | −1000 ~ 1000 | `d300`, `d-300` | Day 4~5 |
| `r<값>` | 목표 RPM | 0 ~ 120 | `r80` | Day 6~ |
| `s` | 즉시 정지 (듀티 0, 목표 0) | — | `s` | 항상 |
| `?` | 현재 상태 출력 | — | `?` | 항상 |

- 범위를 벗어나거나 형식이 틀리면 `ERR`를 출력하고 무시한다. 입력 검증도 실습 내용이다.
- 정상 처리되면 `OK`를 출력한다.

**CubeMX 설정:** USART2 → NVIC Settings → USART2 global interrupt를 Enable로 켠다.

**수신 코드 뼈대 (`cmd.c`)**

```c
static uint8_t rx_byte;
static char line[16];
static volatile uint8_t line_ready = 0U;

void cmd_init(void)
{
    (void)HAL_UART_Receive_IT(&huart2, &rx_byte, 1U);
}

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    static uint8_t idx = 0U;

    if (huart == &huart2) {
        if (line_ready == 0U) {                 /* main이 처리하는 동안은 입력 무시 */
            if ((rx_byte == '\r') || (rx_byte == '\n')) {
                if (idx > 0U) {
                    line[idx] = '\0';
                    line_ready = 1U;
                }
                idx = 0U;
            } else if (idx < (sizeof(line) - 1U)) {
                line[idx] = (char)rx_byte;
                idx++;
            } else {
                idx = 0U;                       /* 너무 긴 줄은 버림 */
            }
        }
        (void)HAL_UART_Receive_IT(&huart2, &rx_byte, 1U);   /* 다음 바이트 수신 다시 걸기 */
    }
}

void HAL_UART_ErrorCallback(UART_HandleTypeDef *huart)
{
    if (huart == &huart2) {
        (void)HAL_UART_Receive_IT(&huart2, &rx_byte, 1U);   /* 오버런 에러 후 수신 재개 */
    }
}
```

- main loop에서 `line_ready`가 1이면 `cmd_parse(line)`을 호출하고, 끝나면 `line_ready = 0`으로 되돌린다.
- 숫자 변환은 `strtol`로 하고, 끝 포인터를 확인해 숫자가 아닌 글자가 섞였는지 검사한다.

**막히면**
- 입력이 안 먹으면 터미널의 줄바꿈 전송 설정(CR 또는 LF)을 확인한다. 위 코드는 둘 다 받는다.
- 몇 글자 받다가 멈추면 `HAL_UART_ErrorCallback`에서 수신을 다시 거는지 확인한다(오버런).

### S-2. 버튼 단계 입력 (UART가 번거로울 때)

- B1을 누를 때마다 값이 단계별로 바뀌게 한다.
  - Day 4: 듀티 0 → 30 → 50 → 70 → 100% → 0
  - Day 6: 목표 0 → 40 → 80 → 120RPM → 0
- 채터링을 막는다. EXTI 콜백에서 `HAL_GetTick()`으로 마지막 입력 후 50ms가 안 지났으면 무시한다.
- 방향 전환이 필요하면 UART(S-1)를 쓴다.

### S-3. Day 3 ADC 대체: 내장 센서 + 3채널 스캔

가변저항 대신 MCU 안에 있는 두 채널을 읽는다. **처음부터 PA0까지 3채널로 설정해 두면** 가변저항이 왔을 때 ADC 설정을 바꿀 필요가 없다.

**CubeMX 설정 (ADC1)**
- IN0(PA0), Temperature Sensor Channel, Vrefint Channel을 체크한다.
- Scan Conversion Mode = Enabled
- Continuous Conversion Mode = Enabled
- Number Of Conversion = 3
  - Rank 1: Channel 0 (PA0)
  - Rank 2: Temperature Sensor
  - Rank 3: Vrefint
  - 세 개 모두 Sampling Time 239.5 cycles. 온도센서는 17.1µs 이상이 필요하다.
- DMA: Circular, Half Word

**코드**
```c
uint16_t adc_buf[3];   /* [0]=PA0, [1]=온도, [2]=VREFINT */
HAL_ADCEx_Calibration_Start(&hadc1);
HAL_ADC_Start_DMA(&hadc1, (uint32_t *)adc_buf, 3U);
```

**환산 (STM32F103 데이터시트 전형값)**
- 전원 전압: `VDDA = 1.20 × 4095 / adc_buf[2]` (VREFINT 전형값 1.20V)
- 센서 전압: `Vsense = adc_buf[1] × VDDA / 4095`
- 온도: `T(℃) = (1.43 − Vsense) / 0.0043 + 25` (V25 = 1.43V, 기울기 4.3mV/℃)

> 주의: RM0008에 따르면 이 온도센서는 칩마다 오프셋이 최대 45℃까지 다르다. 절대 온도가 아니라 **변화량**을 보는 센서다. 손가락으로 칩을 데웠을 때 값이 오르는지 확인한다.

**PA0 처리**
- 가변저항이 없는 동안 PA0은 **점퍼로 GND에 연결해 둔다.** 떠 있으면 값이 제멋대로 튄다.
- 이 상태에서 raw 값의 흔들림(최댓값 − 최솟값)을 기록한다. 이것이 ADC 자체 노이즈다. 가변저항이 오면 이 값과 비교한다.
- 확인용으로 점퍼를 3V3에 잠깐 옮기면 4095 근처가 나와야 한다. **5V에는 절대 꽂지 않는다.**

**완료 기준 (Day 3 대체)**
- [ ] VDDA 계산값이 3.3V 근처로 나온다
- [ ] 칩을 데우면 온도 값이 오른다
- [ ] PA0을 GND와 3V3에 꽂았을 때 0과 4095 근처가 나온다
- [ ] PA0-GND 상태의 노이즈와 이동평균 후 노이즈를 기록했다

### S-4. Day 9 소형 보드 명령: 고정 테스트 시퀀스

소형 보드가 가변저항 대신 정해진 목표 RPM을 순서대로 보낸다.

```c
static const uint16_t seq_rpm[] = {0U, 60U, 120U, 60U};   /* 3초마다 다음 단계, 끝나면 처음으로 */
```

- 0x100 CMD 프레임의 목표 RPM 자리에 `seq_rpm[step]`을 넣어 10ms마다 보낸다.
- 시퀀스가 0RPM을 거치므로 FI-07(고장 후 목표 0을 확인해야 재가동) 시험이 자연스럽게 된다.

## 3. 가변저항 도착 후 할 일 (체크리스트)

### 도착 시점별 범위
- **Day 3~8 사이에 도착:** ①~⑥
- **Day 9 이후에 도착:** ①~⑦

### ① 모듈 확인 (5분)
- [ ] 핀 3개의 라벨을 확인한다 (VCC/GND/OUT 또는 +/−/S)
- [ ] 핀 헤더가 납땜돼 있는지 본다

### ② 배선 (5분)
- [ ] **PA0에 꽂아 둔 GND 점퍼를 먼저 뺀다.** 꽂은 채로 연결하면 가변저항을 끝까지 돌렸을 때 3V3이 GND에 직접 연결된다.
- [ ] VCC → **3V3** (5V 금지), GND → GND, OUT → PA0 (A0)

### ③ Day 3 확인 (15분)
- [ ] 끝에서 끝까지 돌렸을 때 `adc_buf[0]`이 0~4095 근처까지 나온다
- [ ] 손대지 않은 상태의 흔들림을 필터 전과 후로 기록하고, S-3에서 잰 PA0-GND 노이즈와 비교한다
- [ ] `docs/progress.md` 측정값 표에 적는다

### ④ 입력 소스 선택 추가 (30분)
- [ ] UART 명령을 추가한다: `src pot` / `src uart`. 기본값은 uart로 둔다.
- [ ] pot 모드에서는 0~4095를 듀티(Day 4~5) 또는 0~120RPM(Day 6~)으로 바꾼다
- [ ] **데드존:** 2% 미만은 0으로 처리한다. 바닥에서 흔들리는 값 때문에 모터가 움찔하지 않게 한다.
- [ ] **히스테리시스:** 목표 RPM이 ±2RPM 안에서 흔들리면 갱신하지 않는다
- [ ] UART 명령(S-1)은 시험용으로 그대로 남긴다

### ⑤ 안전 인터록 (선택, 20분)
- [ ] pot 모드로 전환하거나 전원을 켰을 때 가변저항이 0(데드존)이 아니면, 0으로 돌릴 때까지 모터 시작을 금지한다
- [ ] 요구사항으로 추가한다: `SR-08: 입력이 0이 아닌 상태에서 시작하지 않아야 한다`. Day 10에서 고장 주입 테스트와 함께 검증한다.

### ⑥ 동작 확인 기록 (15분)
- [ ] 가변저항으로 속도를 조절하는 영상이나 GIF를 찍는다 (README 데모용)
- [ ] 커밋한다: `pot: ADC 입력 소스 추가, 데드존·히스테리시스`

### ⑦ Day 9 이후라면: 소형 보드로 옮기기 (30분)
- [ ] 가변저항을 소형 보드 PA0에 연결한다 (VCC 3.3V)
- [ ] 소형 보드에 ADC + DMA + 이동평균을 설정한다
- [ ] 입력 선택 점퍼를 단다: PB13을 GND에 연결하면 시퀀스 모드(S-4), 비워 두면(풀업) 가변저항 모드
