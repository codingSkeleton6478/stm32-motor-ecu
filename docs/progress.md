## 일지

### Day 0: 2026-10-15
- 한 일: 부품 도착(가변저항 제외). 10일 가이드, 가변저항 대체 계획, 저장소 구조를 준비했다.
- 측정값: 없음
- 막힌 점 / 해결: 가변저항 미도착 → UART 명령(S-1)과 내장 센서 ADC(S-3)로 대체한다.
- 다음: 부품 상태 확인, Day 1 (개발환경, LED·버튼·UART, 로직 분석기)

### Day 6: 2026-10-21
- 한 일:
  - `pi.c/h`: `pi_step(target, measured, dt)`, 조건부 적분 anti-windup(포화 중 오차가 포화를 키우는 방향이면 적분 정지).
  - `ctrl.c/h` 추가: TIM2 ISR 10ms 분기에서 엔코더 → PI → `motor_set`. `motor_set`은 ctrl에서만 호출(main·ISR 경쟁 제거). cmd는 목표값만 변경. `encoder_init`·`ctrl_init`을 TIM2 시작 전으로 이동.
  - UART 명령: `r<rpm>`(0~50), `p<Kp>`, `i<Ki>`(상한 500), `l1`/`l0`(10ms CSV 로그 `t_ms,target_x10,rpm_x10,duty`), `?`(mode, 게인 x100 표시).
  - 튜닝: Ki=0, Kp 5/10/20/40/80/100 → 100에서 지속 진동 → Kp 50. Ki 10/25/50/100/150/200/300 → Ki 300. `CTRL_KP_DEFAULT`/`CTRL_KI_DEFAULT`로 저장.
  - 스텝 응답(0→35 rpm)과 손 부하 복원 시험. 그래프: `captures/day06_step_kp50_ki300.png`, `captures/day06_load_kp50_ki300.png`
- 측정값: Kp 50 / Ki 300, 상승 0.13 s, 오버슈트 0.3 rpm, 정착 0.62 s, 오차 ±0.2 rpm, ISR 약 24 µs (위 표에도 기록)
- 관찰:
  - P 제어 정상상태 rpm(Kp 5/10/20/40/80 → 4.6/10.6/17.3/23.5/28.3)이 Day 5 듀티-RPM 표로 예측한 값(Kp 20/40/80에서 약 17/24/28)과 일치. Kp 5에서 duty 152 = 5 × (35 − 4.6).
  - 엔코더 읽기를 ISR로 옮긴 뒤 1초 로그 직후 rpm이 +10% 튀던 현상이 사라짐(main이 밀려도 10ms 샘플을 놓치지 않음).
  - `d500`이 Day 5의 27.5 → 약 26 rpm. 건전지 소모로 추정(전압 미측정). PI가 보상.
  - 손 부하: 듀티 100%까지 올려 버티고, 뗀 뒤 40 rpm까지 한 번 넘쳤다가 약 0.5초 만에 35 rpm 복귀.
- 막힌 점 / 해결:
  - 처음 PB0 측정을 `d500`(개루프)에서 해 PI 시간이 빠짐 → `r35`에서 재측정.
  - 게인 상한 100이라 Ki를 더 못 올림 → `CMD_GAIN_MAX` 500.
- 다음: Day 7 I2C (INA219 전류, LCD). 미뤄 둔 것: 로그 모드에서 100ms/1초 printf 끄기(`cmd_log_on` 감싸기).

### Day 5: 2026-10-20
- 한 일:
  - 4일차 커밋·`day4` 태그 확인. 모터 전원을 AA×2(약 3V)로 고정하기로 결정.
  - 엔코더 배선: VCC → 5V(CN6), GND → CN6 GND, A상 → PB6(D10, CN5), B상 → PB7(CN7-21, M/F 점퍼). 핀 위치는 UM1724 Figure 13(NUCLEO-F103RB 핀 배치)으로 확인. PB6/PB7이 FT·TIM4_CH1/CH2인 근거는 데이터시트 DS5319 Table 5(LQFP64 58·59번 핀).
  - CubeMX TIM4: Combined Channels = Encoder Mode, TI1 and TI2(4체배), PSC 0, ARR 65535, Input Filter 10(CH1·CH2 모두. fDTS/16, N=5 → 약 1.25 µs 미만 글리치 무시). CH1 Polarity Falling으로 방향 부호 맞춤(정회전 = 카운트 증가).
  - `encoder.c/h`: `encoder_init`, `encoder_update`(10ms 태스크에서 호출), `encoder_get_delta`, `encoder_get_total`, `encoder_get_rpm_x10`. 16비트 카운터 차이를 `int16_t`로 캐스팅해 넘어감 처리, `int32_t` 누적. RPM은 최근 10개(100ms) delta 합의 이동 합으로 계산: `rpm_x10 = sum × 6000 / CPR`(정수 연산).
  - CPR 측정(5바퀴), 듀티-RPM 표(d200~d1000), 3V 최고 RPM 측정.
- 측정값: CPR 3840, 3V 최고 58.2 rpm, 듀티-RPM 표 (위 표에도 기록)
- 관찰:
  - 10ms delta는 d200에서 4~6 카운트뿐이라(1카운트 = 1.56 rpm) 10ms 값으로는 ±20% 출렁임 → 100ms 창으로 해상도 0.156 rpm. 대신 측정 지연이 약 50ms 생김(Day 6 튜닝 때 고려).
  - 출발: d200에서 약 0.4초 만에 정상 속도. 정지(`s`, d1000에서): 약 0.7초 만에 0 rpm.
  - 매 1초 로그 직후 rpm이 약 +10% 튐(예: d1000에서 584 → 643). 1초 태스크의 printf 두 줄이 10ms 태스크를 밀어 한 번을 건너뛰면(`t10=99`), 20ms치 카운트가 10ms 한 칸에 들어가기 때문. 표에서는 제외.
- 막힌 점 / 해결:
  - PB7 위치를 보드에서 못 찾음 → UM1724 Figure 13에서 CN7-21(바깥 열, PB7 글자) 확인. PB6은 D10과 CN10-17 두 곳에 나오며 같은 핀.
  - 출력축을 손으로 돌린다는 안내와 원판(모터축) 돌리기를 혼동. 원판 반 바퀴에 약 15카운트, 되돌리면 정확히 0 복귀 → 신호 정상 확인. CPR은 모터로 돌리며 출력축 깃발로 셈.
  - CubeMX에서 Channel 2 Input Filter가 0으로 남아 있었음 → 10으로 수정.
  - `encoder_get_rpm_x10` 암시적 선언 경고 → `encoder.h`에 프로토타입 추가(선언 없으면 반환형을 int로 추측).
- 다음: Day 6 PI 속도 제어. 스텝 목표 0→약 35 rpm. 제어 루프(엔코더 읽기 → PI → PWM)는 TIM2 ISR로 이동.

### Day 4: 2026-10-18 ~ 2026-10-19
- 한 일:
  - (10-18) TB6612 모듈 핀 헤더 대신 수-수 점퍼선을 납땜해 연결. 신호선은 CN10 안쪽(홀수) 열: PWMA=13번(PA6), AIN2=21번(PA9), AIN1=23번(PA8), STBY=29번(PB5). VCC=3V3, GND=공통 GND(브레드보드 레일).
  - (10-18) CubeMX: TIM3 CH1 PWM(PSC 0, ARR 3199), PA8/PA9/PB5 GPIO 출력. `motor.c/h` 작성: `motor_init`, `motor_enable`, `motor_set(-1000~+1000)`.
  - (10-18) 로직분석기로 PA6 확인: 약 50 µs(20 kHz), High 약 15 µs(30%).
  - (10-19) `.ioc` TIM3 Counter Period 3199 저장, 시험용 `motor_set(300)` 제거.
  - (10-19) S-1 UART 명령: USART2 global interrupt 켬, `cmd.c/h`(1바이트 수신 인터럽트 → 줄 버퍼 → `line_ready` 플래그 → main의 `cmd_poll()`에서 해석). `d<값>`(−1000~1000), `s`, `?`. `strtol` 끝 포인터로 형식 검사, 범위 밖·형식 오류는 `ERR`. `ErrorCallback`에서 수신 재개(오버런 대비). 100ms ADC printf는 잠시 주석 처리.
  - (10-19) 모터 전원선(파워 커넥터 빨강/검정)을 건전지에서 잘라 분리 → 건전지+ → VM, 건전지− → 공통 GND 레일, 모터 빨강/검정 → AO1/AO2 (브레드보드 A~E 줄 경유).
  - (10-19) 듀티 상한 `MOTOR_DUTY_LIMIT` 300 → 1000. 3V는 모터 사양(3~7.5V, 데이터시트) 안이라 100% 허용.
  - (10-19) `d500`/`d1000`/`s`/`d-500`으로 회전, 속도 변화, 정지, 방향 전환 확인. 최소 구동 듀티 측정.
- 측정값: 최소 구동 듀티 정회전 16~18%, 역회전 16%(1회) (위 표에도 기록)
- 데이터시트(DFRobot FIT0450) 메모: 무부하 3V 60 rpm·0.14 A, 6V 160 rpm·0.17 A, 정지 전류 최대 2.8 A. 엔코더 모터축 16펄스 × 120:1 = 출력축 1바퀴 1920(가이드 예상 3840과 다름 → Day 5 실측).
- 막힌 점 / 해결:
  - (10-18) `tim.h` 없음(이 프로젝트는 TIM 핸들이 main.c에 생성됨) → `extern TIM_HandleTypeDef htim3;`로 변경.
  - (10-18) CubeMX 반영이 안 돼 `htim3` 미정의 링크 에러 → `.ioc` 수정 후 Generate Code.
  - (10-18) Generate Code가 USER CODE 밖의 `#include "motor.h"`를 지움 → USER CODE Includes 안으로 이동.
  - (10-18) Counter Period가 65535로 남아 PWM이 약 1.02 ms(약 1 kHz)로 나옴. High는 CCR 960이라 15 µs로 같았다. `main.c`를 3199로 고친 뒤 20 kHz 확인.
  - (10-18) 로직분석기 핀: CH1~CH8은 PulseView에서 D0~D7. PA6 신호는 CN10-13 한 곳뿐이라 PWMA 선을 빼고 그 소켓에 CH1을 꽂아 측정.
  - (10-19) `CMakeLists.txt`에 `cmd.c` 누락 → 링크 실패로 보드에 옛 펌웨어가 남음(adc 로그 계속 출력). `target_sources`에 추가해 해결. VS Code CMake의 "헤더를 추가할까요" 창은 Esc(헤더는 등록 불필요).
  - (10-19) 엔코더 핀이 속도 입력인지 혼동 → 데이터시트 핀표("phase output", "interrupt port")와 예제 코드(엔코더 핀은 `digitalRead`만, 속도·방향은 L298 드라이버 핀으로 `analogWrite`/`digitalWrite`), 실물 실험으로 엔코더는 출력 전용(피드백 센서)임을 확인.
