- 다음: 부품 상태 확인, Day 1 (개발환경, LED·버튼·UART, 로직 분석기)

### Day 4: 2026-10-18 (진행 중)
- 한 일:
  - TB6612 모듈 핀 헤더 대신 수-수 점퍼선을 납땜해 연결. 신호선은 CN10 안쪽(홀수) 열: PWMA=13번(PA6), AIN2=21번(PA9), AIN1=23번(PA8), STBY=29번(PB5). VCC=3V3, GND=공통 GND(브레드보드 레일).
  - CubeMX: TIM3 CH1 PWM(PSC 0, ARR 3199), PA8/PA9/PB5 GPIO 출력. `motor.c/h` 작성: `motor_init`, `motor_enable`, `motor_set(-1000~+1000)`(듀티 상한 30%).
  - 로직분석기로 PA6 확인: 약 50 µs(20 kHz), High 약 15 µs(30%).
- 측정값: 위 표 (눈금 읽기)
- 막힌 점 / 해결:
  - `tim.h` 없음(이 프로젝트는 TIM 핸들이 main.c에 생성됨) → `extern TIM_HandleTypeDef htim3;`로 변경.
  - CubeMX 반영이 안 돼 `htim3` 미정의 링크 에러 → `.ioc` 수정 후 Generate Code.
  - Generate Code가 USER CODE 밖의 `#include "motor.h"`를 지움 → USER CODE Includes 안으로 이동.
  - Counter Period가 65535로 남아 PWM이 약 1.02 ms(약 1 kHz)로 나옴. High는 CCR 960이라 15 µs로 같았다. `main.c`를 3199로 고친 뒤 20 kHz 확인.
  - 로직분석기 핀: CH1~CH8은 PulseView에서 D0~D7. PA6 신호는 CN10-13 한 곳뿐이라 PWMA 선을 빼고 그 소켓에 CH1을 꽂아 측정.
- 안 한 것: 모터 전원 연결, 모터 회전 확인, UART 명령(S-1), 방향 전환, 최소 듀티 측정, 포텐셔미터로 속도 조절. 완료 기준 2개 모두 미달성.
- 다음: S-1 UART 명령 → 모터 전원 연결 → 최소 듀티

### Day 3: 2026-10-18
- 한 일:
  - 가변저항 모듈(SIG/VCC/GND)을 PA0(A0), 3V3, GND에 연결. 보드 사진과 견적서로 부품·핀 위치를 `parts/`에 정리(프로젝트 공유 폴더, 저장소 밖).
  - ADC1 IN0, 연속 변환, 샘플링 55.5 cycles, DMA Circular(Half Word). ADC 클럭은 Prescaler /6으로 10.67MHz(최대 14MHz).
  - `HAL_ADCEx_Calibration_Start` 후 `HAL_ADC_Start_DMA`. 10ms 태스크에서 16샘플 이동평균(합−가장 오래된 값+새 값, >>4), 100ms마다 0~100% 출력, 1초마다 최대−최소 노이즈 출력.
- 측정값: 노이즈 필터 전 2~3 / 후 0~1 count, 범위 0~4095 (위 표에도 기록)
- 막힌 점 / 해결:
  - `ma_buf = {10u}` 초기값 때문에 합이 부족해 unsigned 언더플로 → avg=65535. `{0U}`로 수정.
  - `raw_max` 갱신 줄 누락 → noise 4294963202. 줄 추가. `if`를 `id`로 오타 → 빌드 실패.
  - DMA 완료/절반 완료 인터럽트가 6.4µs마다 발생해 `t10`이 약 65로 떨어짐 → `HAL_ADC_Start_DMA` 뒤에 `__HAL_DMA_DISABLE_IT(&hdma_adc1, DMA_IT_TC | DMA_IT_HT)`. `t10=99`로 회복.
  - 빌드는 됐는데 보드가 옛 펌웨어 → 디버그 Stop 후 F5로 재시작.
  - 처음 CN6 핀 위치를 헷갈림 → 보드 인쇄 글자(3V3, GND, A0) 기준으로 확인.
- 다음: Day 4 (UART 명령 S-1, 모터 드라이버 배선)

### Day 2: 2026-10-17
- 한 일:
  - TIM2 1ms 인터럽트(PSC 63, ARR 999, 타이머 클럭 64MHz). ISR은 플래그만 세우고 main이 10/100/1000ms 태스크 실행. 공유 변수 volatile.
  - PB0(A3) 디버그 타이밍 핀으로 10ms 태스크 주기·실행 시간 측정.
  - LD2 토글을 레지스터 직접 접근으로 구현(RCC->APB2ENR, GPIOA->CRL, ODR, BSRR/BRR). HAL_GPIO_TogglePin 소스와 비교: HAL도 ODR 읽기 + BSRR 쓰기, if 대신 비트 연산.
  - USART3(PB10/D6)에 printf 미러 추가 → 로직 분석기 UART 디코드에서 `tick` 확인.
  - Day 1 남은 측정(LED High 폭, UART 디코드) 완료.
- 측정값: 10ms 주기 10.021 ms, 실행 시간 약 0.83 µs, LED 폭 500.93~500.98 ms (위 표에도 기록)
- 막힌 점 / 해결:
  - while(1) 닫는 `}` 삭제로 빌드 에러 → 복구.
  - 디버거 정지 상태라 LED 꺼진 것처럼 보임 → Continue(F5). Watch로 g_ms_tick 증가 확인.
  - 1MHz 샘플링에서 0.83 µs 펄스 누락 → 12MHz.
  - 보드에 옛 펌웨어 → 재빌드·플래시.
  - CN10-35(PA2)에서 UART 안 보임 → UM1724: SB62/SB63 기본 OFF라 PA2/PA3는 CN9·CN10에서 끊겨 있음. USART3 미러로 해결, 가이드 수정.
- 다음: Day 3 (ADC)

## 미해결 이슈

- [ ] 주기 오차 약 +0.2% (10.021 ms, 500.95 ms) → HSI 오차로 추정. Day 8 CAN 전에 클럭 소스(HSE 가능 여부, UM1724) 재검토.
- [ ] B1 EXTI가 Rising(뗄 때 반응). 가이드는 Falling. 필요하면 CubeMX에서 변경.
- [ ] 핀 헤더 납땜: TB6612는 완료. INA219, CAN 트랜시버, LCD, 소형 보드는 확인 필요
- [ ] M/F 점퍼, AA 건전지 4개 확보 확인
- [ ] 소형 보드 칩 각인 확인 (STM32F103C8T6인지)
- [ ] 가변저항 도착 후 남은 일: `pot_substitute.md` §3 ④(입력 소스 선택, 데드존, 히스테리시스), ⑤(안전 인터록)은 Day 4 이후
- [ ] AA 홀더가 2개입 1개(약 3V). 가이드 부품표는 4구(6V)인데 구매품은 2칸. 일단 3V로 진행하고, 모터가 안 돌거나 데드존이 너무 크면 4구 홀더 구매(가격 미확인)

- [ ] `.ioc`의 TIM3 Counter Period를 3199로 저장(현재 `main.c`만 수정, Generate Code 시 65535로 복귀)
- [ ] `main.c`의 시험용 `motor_set(300)`(시작 시 정회전 30%)는 모터 전원 연결 전에 제거

- [ ] 로직분석기: PWMA 선을 CN10-13에 다시 꽂았는지 배선 확인
